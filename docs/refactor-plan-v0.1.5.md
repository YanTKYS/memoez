# MemoEZ v0.1.5 リファクタリング計画

最終更新: 2026-04-18

## 目的
- 今後の機能追加に備え、UI層・ユースケース層・データ層の責務を明確化する。
- 画面ごとの副作用ロジックを整理し、テストしやすい構造へ改善する。
- Android/iOS リリース作業の再現性を高める。

## リファクタリング対象（優先順）
1. **UI hooks の分割**
   - `useEditNote` を「保存」「ラベル」「削除」責務へ分離。
   - 画面遷移・ダイアログ制御とドメイン処理を分離。
2. **Repository 境界の整理**
   - `DrizzleNoteRepository` の検索・ラベル・チェックリスト更新ロジックを private helper 化。
   - `INoteRepository` の返却型と責務コメントを見直し。
3. **検索機能の拡張耐性**
   - `useSearch` の条件分岐を query builder 相当に整理。
   - ラベル絞り込みとキーワード検索の組み合わせをテスト可能にする。
4. **UI component の責務整理**
   - `LabelPickerSheet` を「選択UI」に限定し、操作導線を明確化。
   - `SearchScreen` のフィルタ表示を再利用可能コンポーネントへ抽出。
5. **テスト基盤の拡張**
   - hooks のユニットテスト追加（save, delete, label attach/detach）。
   - repository のクエリ条件（soft-delete）回帰テストを追加。

## 完了条件（Definition of Done）
- 主要 hooks/repository の責務分割が完了し、1ファイルあたりの複雑度を低減。
- 既存機能（メモ編集、ラベル操作、検索）が回帰なしで動作。
- 追加したテストが CI で安定して green。
- 開発者向け設計メモ（このドキュメント）を更新済み。

## 実施メモ
- v0.1.5 は機能追加よりも内部品質向上を優先する。
- 既存 UX を壊さないことを最優先とし、段階的に分割する。
